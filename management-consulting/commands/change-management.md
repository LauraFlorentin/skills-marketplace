# Change Management

> If you see unfamiliar placeholders or need to check which tools are connected, see [CONNECTORS.md](../CONNECTORS.md).

Develop an organizational change management (OCM) plan to support a transformation initiative, process change, or organizational restructuring.

## Usage

```
/change-management <initiative>
```

### Arguments

- `initiative` — The change being implemented:
  - A process redesign, technology rollout, organizational restructure, or strategic shift
  - Can also be a specific phase: `stakeholder-map`, `communication-plan`, `training-plan`, `readiness-assessment`

## Workflow

### 1. Understand the Change

If ~~documents or ~~project tracker is connected:
- Pull initiative documentation, project plans, and stakeholder lists
- Review scope and timeline of the underlying transformation

If no data source is connected:
> Provide: what's changing, who's affected, timeline, key stakeholders, known resistance points, and desired adoption outcomes.

### 2. Stakeholder Analysis

Map all affected stakeholders across two dimensions:
- **Influence** (ability to enable or block the change)
- **Impact** (degree to which their role, process, or tools will change)

Classify each stakeholder as champion, supporter, neutral, skeptic, or resistor. Develop targeted engagement strategies for each group.

### 3. Impact Assessment

Assess organizational impact across three dimensions:
- **People** — Role changes, skill requirements, reporting structure, headcount
- **Process** — Workflow changes, new procedures, retired processes, handoff modifications
- **Technology** — New systems, retired tools, training requirements, data migration

### 4. Develop Change Plan

Create a comprehensive plan including:
- **Communication plan** — Audience-specific messaging, cadence, and channels
- **Training plan** — Needs assessment, curriculum design, delivery schedule, effectiveness measurement
- **Resistance management** — Anticipated barriers and intervention strategies
- **Adoption tracking** — Metrics and measurement methodology (awareness → understanding → adoption → proficiency)

### 5. Readiness Assessment

Evaluate organizational readiness using a structured checklist covering leadership alignment, resource availability, stakeholder awareness, training readiness, and technical readiness. Define go/no-go criteria.

### 6. Output

Provide:
1. Stakeholder map with engagement strategies
2. Impact assessment summary
3. Communication plan with timeline
4. Training plan with curriculum outline
5. Readiness assessment with go/no-go recommendation
6. Risk flags and escalation items
