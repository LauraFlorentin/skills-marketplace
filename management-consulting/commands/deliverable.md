# Client Deliverable Creation

> If you see unfamiliar placeholders or need to check which tools are connected, see [CONNECTORS.md](../CONNECTORS.md).

**Important**: All deliverables should be reviewed by senior team members before client submission.

Create a structured consulting deliverable for a client engagement.

## Usage

```
/deliverable <type> <topic>
```

### Arguments

- `type` — Deliverable format:
  - `report` — Full assessment or analysis report
  - `deck` — Presentation/slide deck
  - `executive-summary` — One-page executive summary or readout
  - `recommendations` — Prioritized recommendations document
  - `roadmap` — Implementation roadmap
  - `framework` — Custom analytical framework
- `topic` — Subject matter for the deliverable

## Workflow

### 1. Gather Inputs

If ~~documents is connected:
- Pull relevant research, data, and working files from the engagement
- Review prior deliverables for this client to match tone and format

If no data source is connected:
> Provide: key findings, data/evidence, client context, audience, and any prior deliverables for formatting reference.

### 2. Structure the Deliverable

Apply the situation → complication → resolution narrative arc:
- **Situation**: What is the current state?
- **Complication**: What challenge or change requires action?
- **Resolution**: What should the client do about it?

### 3. Draft Content

Build out each section with evidence-based arguments, relevant frameworks, and clear recommendations. Apply the MECE principle and the pyramid principle throughout.

### 4. Quality Check

Verify against the quality checklist:
- Is every finding supported by evidence?
- Is the structure MECE?
- Can a C-suite reader understand the key message in 60 seconds?
- Are recommendations specific, actionable, and prioritized?

### 5. Output

Provide the complete deliverable draft with formatting guidance and any items flagged for team review.
