# Slide Craft Reference

Practical guidance for building high-impact slides: titles, content, visuals, and flow.

---

## The One-Idea-Per-Slide Rule

Every slide should deliver **exactly one message**. When a slide tries to say two things, neither lands.

**Test**: Cover the title and read the content. What is the main message? Now read the title. Does it say the same thing? If not, fix the title.

**Signs you're violating this rule**:
- The slide has two charts
- The title is a topic (not a claim)
- The slide has more than 4–5 bullet points
- You say "and also" when describing what the slide is about

## Action Titles (The Most Important Habit in Business Storytelling)

### Topic titles vs. Action titles

| ❌ Topic Title | ✅ Action Title |
|---------------|----------------|
| Revenue Analysis | Revenue declined 12% YoY driven by volume loss in digital channels |
| Market Overview | Challenger banks have captured 18% of new accounts in 24 months |
| Cost Reduction Options | Three initiatives can reduce operating costs by $85M over 18 months |
| Customer Satisfaction | NPS has dropped 14 points — customers cite speed and digital experience |
| Headcount Plan | We recommend reducing headcount by 8% through attrition, not layoffs |

### Formula for a good action title
[Subject] + [Verb] + [Specific Insight or Implication]

The title should be a **complete, declarative sentence** that delivers the message even if the audience only reads the title and skips the content.

### "So What?" test
Ask "so what?" after any title. If you can't answer it, it's a topic title.

- "Market Overview" → So what? → You don't know. Bad title.
- "Digital adoption grew 3x among 18–34 year olds" → So what? → "We should double digital investment." Good title.

## Slide Anatomy

### Anatomy of a well-built argument slide
```
┌──────────────────────────────────────────────────────┐
│ ACTION TITLE: One-sentence claim (the message)       │
├──────────────────────────────────────────────────────┤
│                                                      │
│  ● Supporting point 1 (specific, not generic)        │
│  ● Supporting point 2 (with a number if possible)    │
│  ● Supporting point 3 (links back to the title)      │
│                                                      │
│  [ONE CHART or VISUAL — annotated with insight]      │
│                                                      │
├──────────────────────────────────────────────────────┤
│  Source / footnote (if needed)                       │
└──────────────────────────────────────────────────────┘
```

### Anatomy of a data slide
```
┌──────────────────────────────────────────────────────┐
│ ACTION TITLE: What the chart proves                  │
├──────────────────────────────────────────────────────┤
│                                                      │
│  [CHART — clean, minimal gridlines, direct labels]   │
│                                                      │
│  ← Annotation pointing to the key data point        │
│    "This spike corresponds to the rate change"       │
│                                                      │
├──────────────────────────────────────────────────────┤
│  Source                                              │
└──────────────────────────────────────────────────────┘
```

## Chart Selection Guide

Use the right chart for the message — not for the data.

| Message you want to send | Best chart type |
|--------------------------|----------------|
| Trend over time | Line chart |
| Comparison across categories | Bar chart (horizontal for long labels) |
| Part-to-whole composition | Stacked bar or Pie (if ≤5 segments) |
| Distribution | Histogram or Box plot |
| Correlation / relationship | Scatter plot |
| Progress toward a target | Bullet chart or progress bar |
| Geographic comparison | Map |
| Two-variable comparison | 2×2 matrix |
| Process or flow | Swimlane or Sankey |

### Chart hygiene rules
1. **Remove all chart junk**: gridlines, borders, legends (when labels are on the chart), background color
2. **Use direct labels** instead of a legend — the audience shouldn't have to decode colors
3. **Annotate** the key data point the title refers to
4. **Use contrast sparingly**: one color for the "hero" data; grey for everything else
5. **Never use 3D charts** — they distort perception
6. **Don't start y-axis at a non-zero value** unless you explicitly note it

## Bullet Point Discipline

### Bad bullet points
```
• Comprehensive review of the digital landscape
• Key findings are important for strategy
• Multiple recommendations
```
These are **topics, not insights**. They contain no information.

### Good bullet points
```
• Digital-only banks grew new account volume 3x faster than incumbents in 2024
• Cost-to-serve for digital-native banks is 40% lower due to no branch overhead
• Regulatory sandbox approvals for neobanks increased 67% in 18 months
```
These are **specific claims with data**. Each one is a mini-argument.

### The 3-bullet rule
Most argument slides need only 3 bullets. If you have more than 5, you probably have more than one idea on the slide.

## Deck Flow and Narrative Continuity

### The "through-line" test
Read just the slide titles in sequence. Do they tell the story without opening any slide? If not, fix the titles before fixing the slides.

### Transition logic between slides
Each slide should raise a question that the next slide answers:

```
Slide 1: "Digital challengers are eroding our market position" 
         → Question: "How bad is it?"
Slide 2: "We have lost 8% market share in 18 months"
         → Question: "What's driving this?"
Slide 3: "Three factors explain the loss: pricing, product gaps, and brand perception"
         → Question: "What should we do?"
Slide 4: "We recommend a three-pillar response..."
```

### Zooming technique
Move from macro to micro (or micro to macro) to create a sense of discovery:

**Wide → Narrow**: "Here's the industry trend. Here's our sector. Here's our firm. Here's the team causing the issue."

**Narrow → Wide**: "One customer complained. Then 100. Then 10,000. This is a product problem — not a segment problem."

## Executive Summary Slide

Every deck should have an executive summary slide at the front. Busy executives will read only this.

### Structure
- **Situation**: 1 sentence of context
- **Complication**: 1–2 sentences on the tension or problem
- **Recommendation**: 1 sentence — your governing thought
- **Key arguments**: 3 bullets that support the recommendation
- **Ask**: What you need from the audience

### Rule: Write the exec summary last, but put it first.

## Appendix Architecture

The appendix is where your analytical credibility lives. Executives won't read it in the meeting — but they'll ask for it afterward.

**What goes in the appendix**:
- Full data tables
- Methodology notes
- Detailed financial models
- Sensitivity analyses
- Alternative scenarios you considered
- Backup slides for anticipated questions

**Label appendix slides** so they're easy to navigate during Q&A: "A1 — Market Sizing Methodology", "A2 — Benchmarking Sample"

## Horizontal and Vertical Logic

Two perpendicular logic systems govern any well-built deck:

**Vertical logic** (within a slide):
- The action title makes a definitive claim
- The slide body provides visual and quantitative evidence to prove it
- Pull any single slide from the middle of the deck — the relationship between title and content should be immediately obvious, without any context

**Horizontal logic** (across the deck):
- Read only the action titles in sequence — you should be able to understand the complete story without opening a single slide body
- This "scannability" is essential for executives who may have minutes to flip through a 100-page deck
- When both systems work together, there is a clean separation of labor: the speaker delivers ideas and conviction; the PowerPoint provides the irrefutable proof

**Test**: Cover all slide bodies and read only the titles out loud. Does it tell a coherent story? If not, fix the titles before touching anything else.

## Ghost Slides (Backup / Appendix Slides)

Every consulting deck should be a "standalone document" — it must communicate fully even without a presenter.

**Ghost slides** are pre-built to handle anticipated challenges:
- Q&A questions you know will come up
- Methodological objections
- Alternative scenarios you considered and rejected
- Supporting data that's too granular for the main narrative

**Label them clearly** for easy navigation during Q&A: "A1 — Sensitivity Analysis", "A2 — Competitive Benchmarking Methodology"

**Rule**: If a data point is important but fails the "so what" test for the main story, move it to the appendix — don't remove it entirely. The appendix is where your analytical credibility lives.

## Layer-by-Layer Information Reveal

To manage executive attention and prevent the "split-attention effect" (audience reads ahead instead of listening):

1. **Start with the high-level summary** — give the 30,000-foot view first
2. **Add layers progressively** — introduce detail as the narrative advances
3. **Use context preservation** — when drilling into a specific detail, keep the broader context visible (e.g., a global map still visible when zooming into a region)

This prevents the audience from "getting ahead" of the presenter and missing the narrative thread.

---

| Mistake | Why it fails | Fix |
|---------|-------------|-----|
| Topic titles | Give no information | Rewrite as a complete sentence claim |
| Too many slides | Dilutes the message | Aim for 1 slide per key argument + appendix |
| Data dumps | Overwhelm, don't persuade | Pick the one number that proves the point |
| No exec summary | Forces busy people to read everything | Always include a summary slide |
| Inconsistent visual theme | Signals lack of attention to detail | Use one template, one color palette |
| Animations and transitions | Distract from content | Remove all except simple fades |
| Font sizes below 18pt | Illegible in projection | Minimum 18pt for body, 24pt for titles |
